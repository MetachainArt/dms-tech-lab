“일반인은 뮤즈, 직장인은 닷츠.” 두 서비스를 이렇게 구분한 설명을 보고, 제가 하던 자동화를 기준으로 확인해봤습니다. 일정이나 문서를 정리하는 정도가 아니라, 지금 Aside와 Claude Code, Codex를 연결해 처리하던 일들을 어디까지 옮길 수 있는지 궁금했습니다.

제 자동화에는 자료 조사와 글쓰기뿐 아니라 블로그 발행, 여러 SNS 계정 운영, 카카오톡 대화 수집, 웹사이트 배포, 영상 제작 등이 섞여 있습니다. 2026년 10월 3일 확인 당시 Aside에 활성 상태로 설정된 반복 루틴은 38개였습니다. 다만 이 숫자는 저장된 루틴 수이며, 38개가 모두 오류 없이 실행된다는 의미는 아닙니다.

먼저 이번 확인의 범위를 분명히 하겠습니다. **뮤즈와 닷츠로 모든 루틴을 직접 옮겨 실행한 후기는 아닙니다.** 현재 작업 지침과 두 서비스의 공식 기능을 대조해, 이전 가능성이 높은 작업과 추가 검증이 필요한 작업을 나눠본 결과입니다. 새로운 서비스의 성능 순위를 매기거나 완료율을 측정한 벤치마크도 아닙니다.

조사·요약·원고 작성은 먼저 옮겨볼 만합니다. 하지만 여러 계정에 글을 올리고, 로컬 프로그램을 실행하고, 밤새 렌더링한 영상을 검수해 게시하는 과정까지 맡기려면 확인할 것이 상당히 많습니다.

*공식 기능과 현재 루틴의 비교입니다. ‘가능성 높음’은 실제 실행 성공을 뜻하지 않으며, ‘미확인’은 불가능 판정이 아닙니다.*

## 지금 쓰는 도구들의 역할부터 구분했습니다

Aside, Claude Code, Codex를 하나의 기능으로 묶으면 비교가 흐려집니다. 제가 사용하는 구성에서 Aside는 예약된 작업을 시작하고, 브라우저와 계정을 다루고, 작업 기록을 이어가는 역할을 맡습니다. Claude Code와 Codex는 필요에 따라 코드를 작성하거나 수정하고, 제작 스크립트와 로컬 작업을 처리하는 데 쓰입니다.

그 아래에는 다시 실제 작업 도구가 있습니다. Blender, 영상 인코더, 이미지 생성 서비스, 웹사이트 저장소, 각 플랫폼의 편집기처럼 결과물을 만드는 데 필요한 환경입니다. 대화창에서 지시를 받는 에이전트만 바뀌어도 그 아래의 프로그램과 계정은 계속 필요할 수 있습니다.

그래서 ‘닷츠로 바꾼다’는 말에도 서로 다른 뜻이 들어갑니다. 작업을 지시하고 관리하는 창구를 바꾸는 것인지, 코드를 만드는 도구까지 바꾸는 것인지, 아니면 영상 제작과 게시 환경을 전부 교체하는 것인지부터 정해야 합니다. 앞의 두 가지가 가능하더라도 마지막까지 저절로 해결되지는 않습니다.

## 뮤즈는 생활 상담 도구에 머물지 않습니다

뮤즈를 쇼핑이나 일정 관리를 도와주는 서비스 정도로 생각하기 쉽습니다. 하지만 [공식 제품 설명](https://introducing.muse.ai/)에는 자체 컴퓨터와 파일 시스템, 터미널, 웹브라우저가 등장합니다. 필요한 코드를 작성하고 문서나 웹페이지를 만들며, 정해진 일정과 관련 이벤트에 따라 작업을 이어가는 기능도 안내돼 있습니다.

이 정도면 자료를 조사해 정리하거나 정기 보고서를 만들고, 웹에서 정보를 확인하는 일은 충분히 시험할 만한 범위입니다. 단순히 답을 얻는 데 그치지 않고 파일이나 결과물을 만들 수 있다는 점에서 기존 자동화와 겹치는 부분이 있습니다.

다만 제 환경에서는 운영체제 차이가 걸립니다. [뮤즈가 로컬 파일과 일부 앱을 다루는 기능은 Mac에서 공식 확인됐습니다.](https://www.meta.com/help/artificial-intelligence/1126304576638594/) 제가 쓰는 Windows PC의 파일, 카카오톡, 전용 Chrome 프로필, 제작 프로그램에 같은 방식으로 접근할 수 있는지는 이번 조사로 확인하지 못했습니다.

클라우드에 자기 컴퓨터가 있다는 사실과, 제 PC에 설치된 프로그램을 그대로 쓸 수 있다는 사실은 다릅니다. 브라우저가 있다는 이유만으로 지금 하던 일을 전부 맡길 수 있다고 판단하면 이 차이를 놓치게 됩니다. Windows 지원 미확인은 서비스 전체에 대한 불가능 판정도 아닙니다. 웹 작업과 로컬 작업을 따로 평가해야 합니다.

## 닷츠는 서류 업무보다 범위가 넓었습니다

닷츠에서 눈에 들어온 부분은 문서 작성보다 로컬 연결 기능이었습니다. [공식 도움말](https://help.openai.com/articles/20001530)에 따르면 닷츠는 자체 클라우드 컴퓨터를 사용하며, 사용자가 허용하면 ChatGPT 데스크톱 앱을 통해 로컬 컴퓨터에도 연결할 수 있습니다. Windows 앱이 제공되고, 연결된 환경에서 로컬 파일과 스킬을 사용하거나 Work·Codex 작업을 만들고 로컬 브라우저를 활용하는 경로도 안내돼 있습니다.

이미 만들어둔 스크립트, 정리된 작업 폴더, 웹사이트 소스를 활용할 여지가 있다는 뜻입니다. 그렇다고 현재 폴더를 연결하는 순간 모든 루틴이 호환된다는 의미는 아닙니다. 실행 명령, 필요한 프로그램, 인증, 파일 권한을 실제 환경에서 확인해야 합니다.

닷츠가 Codex 작업을 만들 수 있다면, 이전 후에도 Codex를 계속 쓰는 구성일 수 있습니다. 닷츠가 모든 제작 도구를 없애는 것이 아니라, 그 도구들에 일을 맡기고 진행을 관리하는 역할을 할 수도 있습니다. 제가 쓰는 Claude Code 환경과 모델 선택, 승인 방식까지 그대로 이어지는지는 별도 확인이 필요합니다.

## 가장 먼저 옮겨볼 만한 일은 조사·요약·원고 작성입니다

메일을 읽고 중요한 내용을 추리거나, 여러 자료를 비교해 보고서를 만들거나, 한글 원고를 영어로 다듬는 작업은 비교적 시험하기 좋습니다. 결과를 검토하기 쉽고, 잘못됐을 때 공개 게시물이나 실제 계정에 곧바로 영향을 주지 않도록 범위를 제한할 수 있기 때문입니다.

예를 들어 Gmail 요약이라면 처음에는 읽기 전용으로 연결하고, 중요한 메일을 빠뜨리지 않는지와 마감 날짜를 정확히 옮기는지를 보면 됩니다. 원고 작성은 같은 자료와 지침을 주고 사실 오류, 표현, 수정에 드는 시간을 비교하면 됩니다. 연결 권한이 넓게 제공되더라도 요약 시험에 발송 권한까지 줄 이유는 없습니다.

제 경우에는 채널마다 말투와 구성도 다릅니다. 이 지침을 옮기지 않은 채 같은 주제만 던지면 문장은 잘 써도 기존 운영 방식과 맞지 않는 결과가 나올 수 있습니다. 이미 만들어둔 글쓰기 기준을 얼마나 잘 따르는지도 이전 시험에 포함해야 합니다. 분량이나 문장 매끄러움만 보고 합격시키면 이후 편집에 드는 시간을 놓칩니다.

## 자동 발행은 원고 작성보다 확인할 것이 많습니다

블로그 글 한 편을 완성하는 일과, 그 글을 원하는 형식으로 공개하는 일 사이에는 여러 단계가 있습니다. 이미지가 서로 다른지, 제목과 본문이 구분됐는지, 제휴 고지가 들어갔는지, 링크가 열리는지, 공개 페이지에서 문단이 무너지지 않았는지까지 봐야 합니다. 글이 잘 써졌어도 편집기에서 이미지가 빠지면 작업은 끝난 것이 아닙니다.

SNS는 계정 관리가 더해집니다. 제가 운영하는 계정들은 같은 서비스 안에서도 용도가 다릅니다. 작성창이 어느 계정으로 열려 있는지 확인하고, 연결글 순서와 이미지 수를 맞추고, 게시 후 실제 결과를 다시 확인해야 합니다. 로그인 상태가 남아 있다는 것만으로 원하는 계정이 선택됐다고 볼 수는 없습니다.

뮤즈나 닷츠에 브라우저 기능이 있다는 것은 이 과정을 시도할 수 있는 근거입니다. 하지만 특정 플랫폼의 편집기를 안정적으로 다루고, 여러 계정을 혼동하지 않으며, 예약 실행에서도 같은 결과를 내는지는 시험해야 합니다. 따라서 블로그와 SNS 자동 발행은 지금 단계에서 ‘불가능’보다 **‘연동과 게시 검증이 필요한 작업’**으로 분류하는 편이 정확합니다.

## 카카오톡·웹사이트·영상은 기존 PC 환경이 중요합니다

카카오톡 요약은 두 단계로 나눠봐야 합니다. 수집된 대화를 요약하는 일과, PC 카카오톡의 여러 방에서 대화를 가져오는 일입니다. 첫 번째는 일반적인 텍스트 처리에 가깝습니다. 두 번째는 현재 수집 스크립트와 Windows 환경에 의존합니다. 닷츠가 PC에 연결되더라도 스크립트가 정상 실행되는지, 빠진 방은 없는지, 지난 24시간의 범위를 정확히 잡는지 확인해야 합니다.

DMS 웹사이트도 글만 쓰면 끝나지 않습니다. 지정된 로컬 원본에서 파일을 수정하고, 기존 변경 사항을 보존하고, 빌드와 배포를 거친 뒤 공개 페이지를 검수하는 절차가 있습니다. 닷츠의 로컬 연결은 이 작업을 옮겨볼 근거가 되지만, 원본 경로와 인증, 저장소 상태를 다시 맞춰야 합니다. 다른 사람이 편집 중인 파일을 함께 커밋하는 실수도 방지해야 합니다.

영상은 의존성이 더 큽니다. Blender 장면을 만드는 코드, GPU 렌더링, 음성, 음악, 인코딩, 자막, 최종 검수가 이어집니다. 에이전트를 바꾼다고 이 제작 환경이 사라지지는 않습니다. 닷츠가 기존 도구를 실행하고 제작을 관리할 가능성은 있지만, 장시간 렌더가 중단됐을 때 정확히 이어서 처리하거나 완성 영상의 품질까지 자동으로 보장한다고 말할 근거는 아직 없습니다.

이런 작업은 짧은 샘플 제작과 장시간 실행을 나눠 검증해야 합니다. 렌더 파일이 생겼다는 사실과 영상의 화면·소리·자막이 시청 가능한 품질이라는 판단도 구분해야 합니다. 기술 검사를 통과해도 사람이 다시 확인할 부분은 남습니다.

## 작업별로 보면 이전의 난도가 달라집니다

| 현재 하는 작업 | 뮤즈 | 닷츠 |
| --- | --- | --- |
| 조사·요약·원고 | 가능성 높음 | 가능성 높음 |
| 블로그 자동 발행 | 연동·검증 필요 | 연동·검증 필요 |
| 다계정 SNS 게시 | 계정·게시 검증 | 계정·게시 검증 |
| PC 카카오톡 수집 | Windows 접근 미확인 | 로컬 연결 후 시험 |
| DMS 코드·배포 | 지정 원본 접근 확인 | 로컬 연결 후 시험 |

토스 관련 비교는 봇 로그와 계좌 상태를 읽는 점검·보고 범위입니다. 실제 주문이나 금융 의사결정을 두 서비스에 맡겨도 된다는 판단이 아닙니다. Aside 백업과 임시파일 정리 역시 내부 작업 상태와 보존 규칙에 의존하므로, 파일 접근만 된다고 같은 기능이 완성되지는 않습니다.

## 예약 기능이 있다고 무인 운영까지 검증된 것은 아닙니다

반복 실행을 지원한다는 설명은 중요합니다. 하지만 실제 운영에서는 시작 시각 이후에 벌어지는 일이 더 복잡합니다. 앞선 작업이 아직 끝나지 않았을 수도 있고 로그인 세션이 만료될 수도 있습니다. 게시 버튼을 누른 뒤 응답이 늦으면 이미 올라간 글을 다시 올릴 위험도 있습니다. 영상 제작이 밀리면 다음 작업과 GPU를 함께 쓰게 됩니다.

현재 자동화에 쌓인 중복 방지 기록, 오류 복구 절차, 계정 확인 규칙은 이런 상황을 다루기 위한 장치입니다. 새 서비스에 작업 설명만 복사한다고 이 기록과 절차까지 자동으로 따라가지는 않습니다. 운영 기록을 어떤 형태로 넘기고, 이후에는 어디를 기준으로 완료를 판단할지도 정해야 합니다.

권한도 다시 설정해야 합니다. [닷츠의 안전·권한 안내](https://help.openai.com/articles/20001529)는 맞춤 규칙으로 일부 작업을 허용하거나 제한할 수 있지만 내장된 안전 요건과 승인 절차를 모두 해제할 수는 없다고 설명합니다. 제 운영 기준에서 외부 문의나 메일 발송 금지, 읽기 전용 점검, 기존 게시물 변경 금지 같은 조건은 이전 후에도 유지돼야 합니다. 원하지 않는 행동을 하지 않도록 옮기는 일이 먼저입니다.

## 비용도 구독료만 비교하면 안 됩니다

[뮤즈의 공식 구독 안내](https://www.meta.com/help/subscriptions/1021145227643680/)에는 무료 사용량과 월 20달러·100달러 요금제가 제시돼 있으며, 지역 제한이 있는 시험 제공 상태라고 적혀 있습니다. 한국에서 제 계정으로 실제 이용할 수 있는지는 이번 확인으로 확정하지 못했습니다.

닷츠는 Pro·Business Premium 등에서 순차 제공되고 첫 dot이 요금제에 포함됩니다. [확인한 Pro 요금제](https://help.openai.com/en/articles/9793128-about-chatgpt-pro-tiers)는 월 100달러·200달러·500달러 단계입니다. 이는 2026년 10월 3일 조사 당시의 안내이며, 가격·제공 지역·사용량은 바뀔 수 있으므로 실제 가입 화면을 다시 확인해야 합니다.

이 금액만으로 제 자동화 전체의 비용을 계산할 수는 없습니다. 기존 이미지·음악 생성 서비스와 영상 제작 환경을 계속 쓰면 그 비용은 남습니다. 작업량 한도, 오류를 고치는 시간, 사람이 검토하는 시간도 함께 봐야 합니다. 로컬 렌더 작업을 연결하면 제 PC의 실행 시간과 자원 사용도 따로 남습니다.

저라면 한 달 구독료보다 같은 작업 열 번을 맡겼을 때 몇 번이나 원하는 결과가 나오고, 수정에 얼마나 손이 가는지를 비교하겠습니다. 이는 앞으로 시험할 기준이지, 이번에 측정한 결과는 아닙니다. 성공 여부는 결과 파일 생성뿐 아니라 내용·형식·권한·공개 상태까지 포함해 미리 정의할 필요가 있습니다.

## 제 선택은 전체 교체보다 작은 작업부터 비교하는 쪽입니다

현재 제 Windows 중심 환경에서는 닷츠를 먼저 시험하는 편이 합리적이라고 판단했습니다. 첫 단계는 메일 읽기 요약과 자료 조사, 비공개 원고 작성입니다. 이후 DMS 글을 초안으로 만들고 로컬 빌드까지 확인해볼 수 있습니다. 그 과정이 안정적일 때 한 개 계정의 제한된 게시 작업으로 범위를 넓히는 순서가 맞겠습니다.

카카오톡 전체 수집, 다계정 동시 운영, 밤샘 영상 제작은 뒤로 두겠습니다. 실패했을 때 영향이 크고 기존 환경과 맞춰야 할 부분도 많기 때문입니다. 뮤즈는 한국 이용 가능 여부와 제 작업 환경에 대한 접근 경로가 확인되면 별도의 가벼운 작업부터 비교해볼 수 있습니다.

이번에 확인한 바로는 ‘뮤즈면 다 해결된다’는 설명은 넓게 잡혀 있고, ‘닷츠는 직장인 서류용’이라는 설명은 좁게 잡혀 있습니다. 지금 제가 가진 자동화 중 상당 부분은 이전을 검토할 만합니다. 다만 어떤 도구가 더 낫다고 결정하려면 제 계정과 파일, 제작 환경에서 같은 작업을 끝까지 수행하는지 확인해야 합니다.

아직 기존 루틴을 교체하지는 않았습니다. 다음 비교에서 보고 싶은 것은 더 그럴듯한 답변이 아니라, 정해진 시간에 시작해 검수를 마친 결과물입니다.
