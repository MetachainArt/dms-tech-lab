[English version](/en/works/claude-code-you-should-know)

AI에게 긴 작업을 맡기면 결과뿐 아니라 읽어야 할 설명도 늘어납니다. 그 안에 남은 조건이나 미확인 사항이 섞여 있으면, 화면에 답이 나왔다는 이유만으로 일을 끝냈다고 생각하기 쉽습니다. Claude Code의 **You should Know**는 이 확인 부담을 줄이려는 기능입니다.

이 글은 2026년 10월 3일 확인한 Anthropic 공식 문서와 발표를 바탕으로 작성했습니다. 직접 사용한 후기나 성능 시험 결과는 아닙니다. 아래의 도입 판단과 시험 절차는 DMS.Labs의 제안입니다.

## 어떤 기능인가요?

Anthropic은 You should Know를 Claude의 출력을 살펴보고 사용자가 놓칠 만한 중요한 정보를 알려주는 기능으로 소개했습니다. 공식 문서에 따르면 긴 작업 중 보조 에이전트가 살펴볼 만한 내용을 발견하면 입력창 위에 메모를 표시합니다. 기본값은 비활성화이며, 조직에 제공되는 경우 플러그인 목록에서 확인할 수 있습니다.

작업 내용을 읽고 중요한 부분을 알려주는 것과 실제 결과가 맞는지 검증하는 것은 다른 일입니다. 메모가 없다고 해서 테스트가 모두 통과했거나 파일이 정상적으로 만들어졌다고 판단하면 안 됩니다. 게시물이라면 공개 화면을, 코드라면 변경 내용과 실행 결과를 따로 확인해야 합니다.

![긴 작업 결과를 확인하기 위한 책상과 화면의 개념 장면](/images/works/claude-code-you-should-know/attention.webp)

## 직접 화면을 보는 긴 작업에 먼저 권합니다

파일 여러 개를 수정하거나 제작 스크립트를 작성하는 작업처럼 출력이 길어지는 상황이 시험 대상으로 적합합니다. 다른 일을 하다가 돌아왔을 때 어디부터 읽어야 할지 찾는 부담을 덜 수 있기 때문입니다. 다만 실제로 검수 시간이 줄어드는지, 중요한 내용을 얼마나 잘 찾아내는지는 자기 작업에서 확인해야 합니다.

짧은 질문에 답을 받는 정도라면 이점이 크지 않을 수 있습니다. 이미 전체 출력을 쉽게 읽는 작업에서는 메모가 하나 더 생기는 셈이기 때문입니다. 모든 세션에 적용하기보다 내용을 놓치기 쉬운 작업 하나를 골라 비교하는 편이 낫습니다.

무인 자동화에는 별도의 판단이 필요합니다. 공식 Mods 문서는 터미널과 Claude Desktop의 Code 탭에서 화면 요소를 표시한다고 설명합니다. 반면 `claude -p`와 Agent SDK에서는 일반적인 Mod 화면 요소가 표시되지 않습니다. 이것을 근거로 You should Know가 모든 비대화형 작업을 감시한다거나 외부 자동화 도구로 알림을 보낸다고 확대해서 설명할 수는 없습니다. 해당 플러그인의 실제 동작과 전달 경로를 따로 확인해야 합니다.

## 사용 전에 확인할 조건

| 확인 항목 | 확인할 내용 |
| --- | --- |
| 버전 | Mods는 Claude Code 2.1.287 이상이 필요합니다. |
| 제공 여부 | `/plugin`의 Installed에서 Show disabled를 열어 내장 항목이 있는지 확인합니다. 조직별 제공 여부가 다를 수 있습니다. |
| 세션 조건 | 2.1.287 출시 안내에는 Anthropic 직접 제공 세션과 텔레메트리 활성화 조건이 적혀 있습니다. |
| 사용량 | 추가 사용량이나 비용 규모를 이 글에서는 확인하지 못했습니다. 무료 또는 사용량 영향 없음으로 가정하지 않습니다. |
| 검수 범위 | 메모는 확인을 돕는 수단입니다. 권한 통제, 테스트, 실제 산출물 검수를 대신하지 않습니다. |

텔레메트리는 이용 분석 정보를 보내는 설정과 관련됩니다. 기능을 쓰기 위해 기존 개인정보·보안 설정을 무조건 바꾸지 마십시오. 회사 환경이라면 조직 정책과 관리자의 설정을 먼저 확인해야 합니다. 제공 대상이 아니거나 정책상 사용할 수 없다면 그 상태에서 멈추는 것이 맞습니다.

## 활성화 방법

터미널에서 설치 버전을 확인합니다.

```text
claude --version
```

버전이 낮다면 진행 중인 작업을 마무리한 뒤 사용하는 설치 방식에 맞춰 업데이트합니다. 새 Claude Code 세션에서 `/plugin`을 열고 Installed → Show disabled에서 `cc-plugin-you-should-know` 제공 여부를 확인합니다. 조건에 맞는 경우 **Claude Code 입력창**에 다음 명령을 넣습니다. 운영체제 셸에 넣는 명령이 아닙니다.

```text
/plugin enable cc-plugin-you-should-know@builtin
```

활성화 후에는 플러그인 관리 화면에서 상태를 확인하고, 범위를 정한 비공개 작업으로 시험합니다. 설명에 없는 별도 마켓플레이스나 이름이 비슷한 외부 플러그인을 대신 설치할 필요는 없습니다. 사용을 중단하려면 `/plugin`에서 해당 내장 플러그인을 비활성화합니다.

## 작은 시험에서 무엇을 기록할까요?

먼저 고객 정보나 비밀이 없는 복사본 프로젝트를 준비합니다. 외부 발행, 삭제, 결제 없이 읽기와 초안 작업만 허용합니다. 이 시험 때문에 원래의 승인 규칙을 느슨하게 만들지 않습니다.

같은 유형의 작업을 기능을 끈 상태와 켠 상태에서 수행하고 나온 메모를 원래 출력과 대조합니다. 완전히 동일한 조건의 성능 측정은 아니므로 한두 번의 결과를 일반화하지는 않습니다. 시작할 때 알고 있는 확인 항목을 적어 두면 도움이 된 부분과 놓친 부분을 구분하기 쉽습니다.

| 기록 | 판단할 질문 |
| --- | --- |
| 도움이 된 메모 | 실제로 다시 읽거나 행동해야 할 내용을 알려줬습니까? |
| 불필요한 메모 | 이미 알고 있거나 이번 작업과 무관한 알림은 없었습니까? |
| 누락 | 사람이 전체 결과를 읽고 발견한 중요한 내용이 빠지지는 않았습니까? |
| 확인 시간 | 메모와 원문을 대조하는 시간을 포함해도 편해졌습니까? |
| 사용량 | 같은 종류의 작업에서 사용량 변화를 확인할 수 있었습니까? |

이 기록은 기능을 계속 사용할지 결정하기 위한 것이지 안전성을 보증하는 점수표가 아닙니다. 유용한 메모가 있어도 원문과 산출물을 확인하는 단계를 남겨 둡니다.

## 자동화 보고 방식에도 적용할 수 있습니다

이 기능을 쓰지 않더라도 완료 보고를 개선할 수 있습니다. **확인한 결과, 아직 확인하지 못한 부분, 사람의 결정이 필요한 일**을 구분해 달라고 요청하는 방법입니다. 긴 설명 마지막에 미확인 사항을 묻어 두기보다 다음 행동을 결정하는 사람이 바로 볼 수 있게 하는 것입니다.

보고 문구가 잘 정리됐다는 이유만으로 실제 검수가 끝난 것은 아닙니다. 영상 파일의 디코딩 성공과 내용을 직접 보는 일은 다르고, 업로드 요청이 받아들여진 것과 공개 페이지를 확인한 것도 다릅니다. 자동화를 설계할 때는 각 완료 주장 옆에 어떤 증거로 확인했는지 남겨 두는 편이 유용합니다.

처음 도입할 때는 화면을 보며 진행하는 긴 작업 하나에서 시작하고 유용한 메모와 누락을 함께 기록하십시오. 관찰 없이 모든 작업에 켜 두는 것보다 자신의 확인 부담이 실제로 줄었는지부터 판단할 수 있습니다.
